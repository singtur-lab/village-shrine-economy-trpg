# 村の神社 経済TRPG — プレイテスト仕様 α v0.1

- 状態: プレイテスト用の仮仕様
- 根拠: ユーザー提供のMeta AI整理資料4点。元の仕様書・全会話ログは未入手
- 目標: 経済成長、銀行運営、連合形成、共同体への還元を、チャットで遊べる形にする
- 固定しないもの: 初期数値、年齢対象、3年で終了するか、イベント方式、ライセンス

## 1. コンセプト

プレイヤーは村の相談役として、暮らしを守りながら銀行・交易・投資・人の交流を育てる。中心の問いは「どれだけ資産を増やすか」だけでなく、「増えた富と信用を何に使い、外へ出た人とどう約束するか」。

神社は架空世界の共同体施設として扱う。現実の信仰や加入を求めず、特定の神名・教団名も使わない。

## 2. 1か月の進行

1. **月初報告**: 人口、生活状態、共同会計、銀行、取引・還元契約、未解決案件を短く示す。
2. **今月の出来事**: 日常・機会・困難のいずれかを提示する。出来事は過去の選択、季節、村の状態に結びつける。
3. **相談**: プレイヤーの希望を聞き、必要なら目的、関係者、使える資源、心配事を確認する。短い入力も受け入れる。
4. **住民の声と選択肢**: 賛成、懸念、代案を紹介し、費用・時間・人手・リスクを比べる。
5. **決定と実行**: 担当、予算、期限、約束を記録する。大きな施策は複数月に分ける。
6. **月末締め**: 会計と村の状態を更新し、結果、差分、未解決事項を示す。

文章の長さを参加条件や報酬条件にしない。プレイヤーが考えを整理したいときだけ、任意の型を示す。

> 何をしたい？／誰にどんな変化がある？／使えるものと心配なことは？

## 3. 状態の最小セット

### 暮らし
人口、食料・住居・健康の状態を、具体的な不足が分かる粒度で記録する。細かい設備目録は必須にしない。

### 共同会計
共同現金、当月収入、当月支出、目的別基金を記録する。基金への割当と実際の支出を分ける。

### 銀行
預金（銀行の負債）、準備金・手元流動性、融資残高、利息収入、預金利息・運営費、延滞・貸倒れを別々に記録する。共同会計や神社口座と混ぜない。

簡易計算:
- 月次純収支 = 当月の実収入 − 当月の実支出
- 融資残高 = 前月残高 + 新規貸出 − 元本返済 − 貸倒処理
- 銀行の月次損益 = 受取利息・手数料等 − 支払利息・運営費・貸倒れ
- 口座間の振替は村全体の新しい利益として数えない

### 地域関係・約束
取引先・連合参加村、融資契約、外出・留学・出稼ぎからの還元契約、履行期限を記録する。

### 信頼・満足
0〜100などの数字は試験時だけ使用し、変化理由を必ず説明する。0で即ゲーム終了にはしない。低下した場合は、説明・返済計画・再合意などの修復機会を設ける。

## 4. 経済の暴走を防ぐルール

- 各事業には生産能力、働き手、需要、季節性、費用、維持負担を設定する。資金投入だけで売上が無限に伸びないようにする。
- 拡大は選択肢の一つ。人口や売上を増やさず、既存の暮らしを整える選択にも価値を持たせる。
- 融資上限は借り手ごとの合計残高で判定し、複数回に分割して上限を回避できない。
- 貸出前に利率、期間、返済方法、担保、遅延時の相談方法を共有する。貸倒れの可能性を消さない。
- 金利差を設けるなら、担保・期間・返済能力などの根拠を明示する。加入資格だけを理由に罰金利を設定しない。
- 投資収益は保証しない。予測と確定収益を分け、失敗・遅延・分散の選択肢を扱う。
- 最低準備額、金利、融資上限はシナリオ設定値。テスト資料の「2000枚」「年5%」「年20%」を普遍的なルールとして転記しない。
- とみくじは標準ルールに含めない。追加する場合は任意の拡張として、架空通貨のみ、費用・賞金原資・損失上限を公開する。

## 5. 還元契約

外へ出る人に共同体への貢献を強制せず、本人が望む場合に「何を学ぶ／持ち帰るか」「いつ振り返るか」を一緒に決める。健康、家庭事情、本人の意思を優先し、達成できない場合は契約を話し合い直す。技能・知識・人のつながりも還元として認める。

## 6. イベント方式（比較テスト用）

資料では2D6が仕様にあったが未使用と報告され、事件カード案も提案されている。どちらもAIの擬似処理であり、完全な乱数とは称さない。

αテストでは次の方式を比較する。

- **A: 擬似2D6** — 出目と日常／兆し／重大イベントの区分を先に宣言する。
- **B: イベント表** — 12件程度の「日常・機会・困難」を含む候補から選び、直近の選択履歴を記録して偏りを確認する。

重大な困難は兆候・選択肢・代償・結果・回復策を含める。無条件の破滅、連続する罰、常に失敗するカード比率は設けない。拡大に伴う管理負担や環境影響は、プレイヤーに予告し選択できるようにする。

## 7. 章と終了（テスト仮説）

まずは12か月を1章として、開始時にプレイヤーと具体的な目標を決め、12か月目に会計・暮らし・約束を振り返る。3章（36か月）を一区切りとする案をテストするが、これは確定仕様ではない。続ける場合、字数や特定の手紙を条件にせず、次の章で何をしたいかをプレイヤーと相談する。

目標の達成だけを採点しない。途中で何を守ったか、どの仕組みを作ったか、約束をどう見直したか、次に何を選ぶかを振り返る。

## 8. 事実・推定・設計の区別

- **提供資料のログ確認主張**: 資料が会話ログで確認できると述べる情報。原ログ未入手につき独立確認前。
- **資料上の数値・出来事**: 提供資料に記載されているが、元ログで再照合できないもの。
- **推定・GM即興**: 提供資料自身が根拠不足と明記している値や規則。
- **設計仮説**: このα仕様で新たに定め、次のテストで検証する内容。

4,500人、月18,000枚、投資年20%などの数値は、テスト報告上の記載としてのみ保管する。標準成長率や約束された成果には使わない。元仕様書・会話ログが入手できたら照合して改訂する。

## 9. 次のテストで測ること

- 短い発言を許容しつつ、目的・制約・関係者の情報を自然に引き出せるか。
- 会計の区分（共同現金、預金、銀行準備金、融資、神社口座）が混ざらないか。
- 分割借入・架空の売上増・複利で資金が無限化しないか。
- 事業拡大と、維持・休止・地域還元の選択が同じ程度に意味を持つか。
- イベント方式A/Bで、多様性・予告・選択の納得感に差が出るか。
- 12か月の終わりに、自然な振り返りと続行判断ができるか。
