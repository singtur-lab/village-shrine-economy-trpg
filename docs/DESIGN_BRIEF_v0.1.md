# 村の神社 経済TRPG — 設計ブリーフ v0.1

- 状態: 設計仮説。プレイ可能な確定仕様ではない
- 形式: チャット専用TRPG
- 独立性: 「異世界村育成TRPG」と別プロジェクト
- 企画の根拠: ユーザー提供のMeta AIプレイテスト整理資料4点
- 注意: 初期仕様書と会話ログの原本は、この資料群には含まれていない

## 1. ゲームの核

プレイヤーは、神社を持つ村の相談役として、銀行、交易、共同出資、外へ出る人との還元契約を使い、村と周辺地域の暮らしを運営する。お金を最大化することが終点ではない。共同体に蓄積した信用や富を、何に使い、どんな約束を守るのかを考える。

「神社」は世界設定上の場として扱い、現実の宗教への加入・信仰を要求しない。テストにあった固有の神名や教団名は持ち込まず、宗教組織に権力を集中させない。

## 2. 遊びの柱（仮説）

1. **銀行の信用を守る** — 預金・準備金・融資・返済を見える形にし、貸せる額と守るべき現金を区別する。
2. **地域間の助け合いを契約にする** — 留学・出稼ぎ・交易で得た知識や成果を、本人の合意に基づく還元契約として記録する。
3. **豊かさの使い道を話し合う** — 余剰ができた後に、教育・福祉・文化・新たな事業など何を選ぶかを問う。
4. **拡大には負担も生じる** — 管理コスト、競争、供給不足、環境負荷、返済遅延などを、兆候と選択肢を伴うイベントとして扱う。
5. **約束と会計を公開する** — だよりや月次報告で、収入・支出・契約・未解決事項を住民と共有する。

## 3. 標準ターンの案

1. 月初に、村の暮らし・共同資金・銀行・融資・約束の状況を簡潔に報告する。
2. 日常の案件または外部イベントを一つ示す。
3. プレイヤーの希望を聞き、必要なら「目的・困っている人・使える資源・心配なこと」を短く確認する。
4. 住民の意見、費用、時間、リスクを示す。
5. 行動を決め、合意・担当・期限を記録する。
6. 月末に、帳簿と社会面の変化、未解決の約束を更新する。

文章の長さは参加条件にしない。短い入力も受け止め、考えを深めたい場合にだけ質問や任意テンプレートを出す。評価するのは字数ではなく、目的・条件・影響を理解し、話し合いや振り返りに参加したこと。

## 4. 状態管理の案

一つの数値だけで村を表さず、次のまとまりに分ける。

- **暮らし:** 人口、食料・住居などの基本状況、健康上の課題
- **共同会計:** 共同現金、月次収入・支出、基金の指定額
- **銀行:** 預金、準備金、融資残高、利息収入、延滞・貸倒れ
- **地域関係:** 加入村、取引先、契約、未達成の還元約束
- **共同体:** 信頼・満足の変化とその理由

標準プレイでは細かい設備一覧を必須にしない。大事な施設だけ記録する。金額の上限を一律100枚とは決めず、シナリオに合う小さな単位を選び、収支が追える範囲に保つ。銀行の最低準備額も固定2000枚ではなく、初期条件と預金規模に応じて設定する。

## 5. 経済ルールのガードレール案

- 融資上限は借り手単位の総残高で判定し、分割借入で回避できないようにする。
- 利率・返済期限・担保・延滞時の相談手順を貸出前に示す。高利が自動的な利益にならないよう、返済不能や貸倒れの可能性を扱う。
- 投資収益は保証しない。期待値と実績を分け、損失・遅延・分散投資の選択肢を示す。
- 仲間かどうかだけで不当に金利を分けない。条件差を置く場合は、期間・担保・返済能力などの理由を説明する。
- とみくじはコア進行から外し、採用する場合も任意の拡張ルールとして、賞金・費用・損失上限を明示する。現実のお金は使わない。
- 共同資金と銀行資金、売上と利益、預金と銀行の自己資本を混同しない。

## 6. 章立てと終わり方（未決）

提供資料には12年のプレイ記録がある一方、改善提案は3年で一区切りにする案を示している。現時点では決定事項ではない。

次の試作仮説として「1年12ターンで章末レビュー、全3章で一区切り」を試す。延長は字数条件にせず、プレイヤーが続けたい理由と次章のテーマを短く相談して決める。各章の終わりに、目標・資金・住民の暮らし・未履行契約を見直す。

## 7. イベントの検証

2D6はテスト仕様にあったと報告されているが、実プレイでは使われなかったとの記録がある。改善案の事件カードも、AI自身が引く限り乱数の透明性を保証しない。

初回の比較テストでは次の2方式を比べる。

- **擬似2D6:** 毎月出目と区分を先に宣言し、その区分に沿ってイベントを出す。
- **イベントカード:** 事前に作ったカード表から選び、最近出たカードを記録して重複を抑える。

どちらも完全な乱数とは扱わない。比較するのは、イベントの偏り、予告の分かりやすさ、記録のしやすさ、プレイヤーが準備を活用できたか。

## 8. 出典と確度の管理

このブリーフでは、次のラベルを使う。

- **確認済み（提供資料内）:** 添付資料が会話ログで確認できると述べている内容。原ログそのものとの独立照合は未実施。
- **資料上の主張:** 報告に数値や出来事が書かれているが、原ログが未添付で再確認できないもの。
- **推定・GM即興:** 資料自身が固定ルールや根拠ログのない数値としているもの。
- **設計仮説:** これから遊んで検証する提案。

人口や売上、利率、投資収益などの数値を、新仕様の確定値として転記しない。特に「12年で人口4500人」「年利20%」などは再現実績として扱わず、シナリオの初期値や標準成長率にしない。

## 9. 次のプレイテスト

1. 短い入力と任意テンプレートで、プレイヤーが意思を表現できるか比べる。
2. 融資枠を分割しても超えられないことを確認する。
3. 収益の高い月と、返済遅延・交易停止が同じ会計で矛盾なく処理できるか試す。
4. 村が増えるほど管理負担や外部影響が増え、拡大しない選択も意味を持つか試す。
5. 12ターン目で目標・会計・住民の変化を振り返り、次章を続けるか自然に選べるか確認する。
6. 擬似2D6とカード方式を同じ初期条件で比較し、どちらがGMの多様な展開を安定させるか確認する。
